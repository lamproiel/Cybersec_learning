# компьютерные сети

## модель TCP/IP: не OSI (это теория), а именно TCP/IP - то, на чём живёт интернет

### 4 слоя TCP/IP
- TCP/IP - 4 слойная модель, которая описывает как устроен инетрнет и как комтьютерны обмениваются
данными. OSI (семиуровненая модель), но TCP/IP проще и практичнее - она описывает именно то, что
реально работает в интернете.

| Слой | Название | Функция | Примеры протоколов | Примеры данных |
|------|----------|---------|--------------------|----------------|
| 4 (Application) | Прикладной | Взаимодействие с пользователем (браузер) и сервером | HTTP, HTTPS, DNS, SSH, FTP, SMTP, POP3, Telnet | Веб-страницы, письма, команды |
| 3 (Transport) | Транспортный | Доставка данных между приложениями на разных компьютерах | TCP, UDP, SCTP | Потоки данных, порты (80, 443, 22) |
| 2 (Internet) | Межсетевой | Маршрутизация и адресация между сетями | IP (IPv4, IPv6, ICMP, IGMP) | IP-адреса (192.168.1.1), пакеты |
| 1 (Netowrk) | Канальный | Передача по физическому кабелю/радио | Ethernet, WI-FI (802.11), PPP, ARP | MAC-адреса, фреймы, биты |

- прикладной слой - правила, по которым программы обмениваются данными. Браузер и сервер используют
протокол HTTP или HTTPS. DNS используется для поиска IP-адреса по имени. SSH используется для удалённого
управления. 
- транспортный слой - доставляет данные между конкретными процессами на этих компьютерах с помощью портовю
	- твой пк: 192.168.1.20:50021 (50021 - временный порт клиента)
	- сервер: 142.250.190.14:443 (443 - порт HTTPS на сервере)
	- порт 80 обычно HTTP без шифрования, а 443 - для HTTPS с TLS-шифрованием.
	- TCP - надежная доставка потока данных: нумерует части, проверяет подтверждения,
обнаруживает потерю и повторно отправляет данные.
	- UPD - тоже транспортный протокол, но не устанавливает полноценное соединение и не 
гарантирует доставку каждой части.
- межсетевой слой - отвечает за IP-адреса и маршрутизацию.
	- пк - домашний роутер - сеть провайдера - другие маршрутизаторы - сервер
	- домашний роутер имеет внутренний адрес (пк) и внешний адрес: адрес, выданный провайдером
- канальный слой - передача данных между соседними устройствами в одной локальной сети. Здесь
используются Ethernet-кадры, MAC-адреса, Wi-Fi и правила доступа к среде передачи.
	- например пк хочет отправить пакет серверу гугл. Он не знает MAC-адрес сервера гугл и не
должен его знать. Он отправляет локальный кадр на MAC-адрес домашнего роутера.

- полная картина такая:
	- браузер создает HTTPS-запрос
	- TCP добавляет порты и обеспечивает надежную доставку
	- IP добавляет адреса и выбирает направление через маршрутизаторы 
	- Wi-Fi/Ethernet передает кадр ближайшему устройству.

### как данные движутся: инкапсуляция и декапсуляция
- когда ты отправляешь данные (вниз по слоям) - **инкапсуляция**
	- (приложение) ты пишешь письмо в Gmail
	- вниз HTTP-пакет
	- (транспорт) добавляется TCP-заголовок с портами (src:54321, dst:443)
	- вниз TCP-сегмент
	- (интернет) добавляется IP-заголовок с адресами (src:192.168.1.100, dst:8.8.8.8)
	- вниз IP-пакет
	- (канал) добавляется Ethernet-заголовок с MAC-адресами (кто в локальной сети)
	- вниз Фрейм
	- (сеть) данные летят по кабелю или WI-FI как биты
	- каждый слой добавляет свой заголовок (envelope) - это называется инкапсуляция. Результат: маленькая HTTP-странница превращается в гору заголовков.
- когда данные приходят (вверх по слоям) - **декапсуляция**
	- (сеть) приходит фрейм с битами
	- (канал) убираем Ethernet-заголовок - видим IP-пакет
	- (интернет) убираем IP-заголовок - видим TCP-сегмент
	- (транспорт) убираем TCP-заголовок - видим HTTP-данные
	- (приложение) браузер получает HTML и рисует страницу
